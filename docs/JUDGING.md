# Demo and judging access

This is an AI-generated ASL accessibility prototype with a native desktop Twitch Component Extension and OBS fallback.

## Before recording

Validate live AWS transcription, Signvrse availability/ASL quality, native Twitch authorization/video playback, two test accounts, and OBS. Add judges’ Twitch test accounts to the allowlist if public release is not approved. State the release status explicitly. Provide repository setup, a reachable hosted companion, and fallback access; do not rely on a private test-only extension as the only way to assess the project.

## Under-three-minute video

1. Identify the accessibility problem and show the broadcaster companion.
2. Speak new short phrases and show actual signing inside the Twitch Component Extension.
3. Show two viewers. Replay/hide signing for one while the other stays live.
4. Show OBS fallback using the same feed, plus pause/stop.
5. Briefly show Codex implementation evidence, repository, and known limitations.

Caption the demonstration in English. Do not present synthetic test patterns or predetermined demo transcripts as real interpretation. Record and supply the Codex session ID from the app; this code does not invent or infer it.

Recheck competition deadlines, ownership, third-party API permission, repository/judge access, and current official rules before submission. No registration or submission is performed by the application.
